## 4. Sideload on a virgin handset

The APK from step 3 → install on a handset that has **never had
ServGrid** (a fresh install, not an upgrade):

- Copy the APK (USB / `adb install -r app-release.apk` / download the
  EAS artifact URL in the handset browser).
- Accept the "install unknown apps" grant for the source app when
  prompted. **If this grant is locked by an OEM policy** (MDM,
  "install unknown apps" admin-blocked, Play Protect hard-refusing) —
  STOP: that is the project-level distribution failure PLAN-EXECUTION
  Phase 0 describes. Do not improvise; record the handset/OEM/model
  and raise it the same day.

## 6. Data-only push, end to end — the actual proof

With the app running on the handset (dev client or a `__DEV__` build
so the token is visible):

1. Get the FCM token from the handset:
   `adb logcat -s ReactNativeJS` → `[push] FCM token: ...`
   (Phase 0 dev-only log, `src/push/push.ts`.)
2. From athena:
   ```bash
   cd /mnt/storage/Study/ServGrid/apps/api
   FCM_SERVICE_ACCOUNT=../../secrets/fcm-service-account.json \
     node tools/fcm-probe.mjs '<device-token>' --data type=data-only-sync
   ```
3. **Pass** = FCM responds `ok: true` AND the handset syncs AND the
   local confirmation ("New work synced — open the app to review")
   appears in the tray. Record both halves in the issue.

### 6b. If the backgrounded app does not react

Data-only delivery **while backgrounded/killed** depends on the app
linkage expo-notifications sets up; if the message arrives only when
foregrounded, the decision tree:

1. **Check `getDevicePushTokenAsync` ran in the probe build** (the
   token exists ⇒ registration path is live).
2. Foreground delivery works but background doesn't → the wake is
   being coalesced by the OS with no notification to show. Move the
   probe to a `notification + data` message shape **in the probe
   only** (data stays authoritative) and re-test: if the tray
   notification arrives, the app-linkage route is the Phase 0 answer;
   record the finding — the Phase 2 assignment notifier needs it.
3. Still nothing → check the Firebase project's Android app package
   name matches `com.servgrid.app` exactly; mismatched packages drop
   messages silently.
4. Add `expo-notifications`'s local `push` receipt debug or EAS `meta`:
   `npx expo-cli` isn't needed — `adb logcat` with
   `FirebaseMessaging` filter shows FCM's own logs on the handset.

Every outcome of 6b is still a **result**: T0.15 exists to surface the
risk while it is cheap, and any "won't deliver in background" finding
goes to the owner the same day with the probe JSON attached.
